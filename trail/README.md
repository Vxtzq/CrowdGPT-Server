# Trail-Code Integration

This repo uses [Trail-Code](https://github.com/trailhq/Trail-Code) (formerly "graft") as a
self-learning context layer for coding agents. It gives Claude Code, Cursor, Codex, and
other agents a map of the codebase and a memory of past decisions, so they pick up where
you left off instead of starting blind every session.

## What's set up

Two parts are active:

1. **The graft map** (`.trail/cache/`) — a code graph built by parsing every file,
   function, method, and class with tree-sitter. Currently 452 nodes and 1,112 edges
   across 22 Python files. This is a local cache (git-ignored) that rebuilds automatically
   when code changes.

2. **Learnings** (`.trail/learnings/`) — decisions, corrections, and knowledge saved from
   agent conversations. These accumulate over time as Claude Code sessions work on the
   codebase. Currently empty; they populate as you use it.

The Claude Code hook in `.claude/settings.json` runs on every session start, injecting
relevant code context and learnings into the agent's prompt.

## Why it helps

Without Trail-Code, a coding agent starts every task cold:

- Greps terms, opens files, follows imports, backs out, tries again
- Re-discovers code a teammate already figured out last week
- May undo a teammate's decision because it never knew about it
- Burns most of a run's tool calls, tokens, and time on rediscovery

With Trail-Code, the agent:

- Gets the right files and functions with every prompt
- Starts from what you and your team already know
- Sees the "blast radius" (what depends on a file) right after editing it
- Saves learnings for the next session (yours or a teammate's)

Measured results from Trail-Code's benchmarks:
- **SWE-bench Verified**: 33/50 issues solved vs 27/50 without (Claude Sonnet 5)
- **162 runs benchmark**: 32% lower cost, 42% fewer uncached input tokens, 60% less time
- **PocketBase (15 real tasks)**: 21% cheaper, 14% faster

## How to set up your own workstation

### Prerequisites

- Node.js 22.3 or newer (20.16 works too)
- npm 10+

### One-time install

```bash
# Install the Trail-Code CLI globally
npm install -g @trailhq/trail-code
```

If `npm install -g` gives EACCES errors (global folder needs sudo), set up a user-level
prefix instead:

```bash
mkdir -p ~/.npm-global
npm config set prefix ~/.npm-global
# Add ~/.npm-global/bin to your PATH in ~/.bashrc or ~/.zshrc
export PATH="$HOME/.npm-global/bin:$PATH"
# Open a new terminal, then install again
npm install -g @trailhq/trail-code
```

### In this repo

The setup is already committed. After cloning:

```bash
# Build the local graft map cache (fast, deterministic, no API key needed)
trail build

# Verify it's working
trail status
```

That's it. Your Claude Code sessions will automatically pick up the Trail context via
the `.claude/settings.json` hook.

### In a new repo

```bash
# Initialize Trail-Code (builds map, sets up .trail/, wires your agents)
trail init

# Choose which agents to wire up when prompted
# Then commit the setup so teammates get it:
git add .claude .mcp.json .trail .gitignore .ignore
git commit -m "set up Trail-code"
```

Note: `graft/` (the map cache) is added to `.gitignore` automatically — it's a local
cache like `node_modules`.

### Useful commands

```bash
trail build           # Rebuild the graft map (also runs automatically)
trail build --deep    # Add plain-English summaries (requires model API key)
trail status          # Check map and learnings status
trail grep <term>     # Search the code graph
trail map             # Orient yourself in the codebase
trail check           # Flag learnings that conflict with current changes
trail viz             # Open the visual graph viewer
```

### How it works under the hood

- **Deterministic parsing**: tree-sitter parses your code into a graph. No model, no
  network, no API key needed for the basic map. Supports 24 languages.
- **Always fresh**: every query checks the working tree first and rebuilds only what
  changed, including uncommitted edits.
- **Plain files**: the map is linked markdown nodes your agent opens and greps like any
  other file. No embeddings, no index to keep warm.
- **Learnings are files**: saved as markdown in `.trail/learnings/` that you can read,
  edit, or delete.

### Privacy

- The graft map is built locally from your code. No code leaves your machine.
- Learnings are saved locally in `.trail/learnings/` (committed with the repo if you
  want teammates to see them) or in `~/.trail/` for personal learnings (never committed).
- `trail build --deep` summaries are generated by your chosen model provider under your
  own API key.

## Coming from graft?

Trail-Code is the successor to graft. The code map is now called the "graft map" and
every `graft` command still works. `trail` is the new command name; `graft` is a
compatibility alias.
